# Project Ditto

A Game Boy Advance game built on the `pret/pokeemerald` decompilation. The goal is one game spanning Hoenn, Kanto (with the Sevii Islands) and Johto, with a single authored story route and all 386 Gen 1–3 Pokémon obtainable in one solo playthrough.

Decisions made so far, and the questions still open for the group, live in [docs/ditto/design.md](docs/ditto/design.md). Read it before proposing design changes; do not treat an open question as decided.

## Build and run

Requires devkitARM (`DEVKITARM=/opt/devkitpro/devkitARM`) and libpng.

```bash
make modern -j$(sysctl -n hw.ncpu)   # builds pokeemerald_modern.gba
open -a mGBA pokeemerald_modern.gba  # play it
```

- Always use `make modern`. Plain `make` needs the legacy agbcc compiler and tries to match the original ROM byte-for-byte, which no longer applies once we change anything.
- A full build takes about 45 seconds; incremental builds are a few seconds.
- After changing a tileset or graphics file, if the result looks stale, run `make tidymodern` and rebuild.
- "It builds" is the minimum bar for every change. For anything visible, also load the ROM in mGBA and look.

## Hard rules

- Never commit ROM files (`*.gba`), saves or build output. `.gitignore` already covers them; do not override it.
- Only Gen 1–3 content: 386 species, no later-gen Pokémon, moves, abilities or Megas. Fairy type is an open question, so do not add it.
- Levels are fixed per area and authored along the story route. Do not add runtime level scaling.
- One person or agent edits a given map at a time. `map.json` and `map.bin` merge badly.
- Kanto and Sevii content is ported from `pret/pokefirered`, keeping FireRed tilesets for now. Port layouts faithfully; redesign comes later.

## Save-file space is nearly full

The build prints memory usage. On the unmodified game, `SaveBlock1` is 99% used, `SaveBlock2` 98% and `PokemonStorage` 94%. Every new flag, variable or saved struct costs save space we do not have. Before adding any, check `include/constants/flags.h` and `include/constants/vars.h` for unused entries to reuse, and report the new usage figures from the build output. ROM space is not a concern (40% of 32 MB used).

## Where things are

| What | Where |
|---|---|
| Map headers, events, connections, scripts | `data/maps/<MapName>/map.json`, `scripts.inc` |
| Map tile grids | `data/layouts/<LayoutName>/map.bin`, `border.bin`; index in `data/layouts/layouts.json` |
| Map list and groups | `data/maps/map_groups.json` |
| Tilesets | `data/tilesets/`, `src/data/tilesets/` |
| Wild encounters | `src/data/wild_encounters.json` |
| Trainers and their parties | `src/data/trainers.h`, `src/data/trainer_parties.h` |
| Species stats, evolutions | `src/data/pokemon/species_info.h`, `src/data/pokemon/evolution.h` |
| Moves | `src/data/battle_moves.h` |
| Flags and variables | `include/constants/flags.h`, `include/constants/vars.h` |
| Engine code | `src/`, headers in `include/` |

The `.inc` files beside each `map.json` (`header.inc`, `events.inc`, `connections.inc`) are generated by the build. Edit `map.json`, never those.

## Maps and Porymap

Humans edit maps in Porymap (open this folder as the project). Agents edit the same files directly: `map.json` is plain JSON, and `map.bin` is a grid of 16-bit little-endian values, one per tile, with the metatile id in the low 10 bits, collision in the next 2 and elevation in the top 4.

Our own tooling goes in `tools/ditto/` and is written in Python. Nothing is there yet. Planned: a map reader and PNG renderer (so an agent can see a map), a FireRed-to-Emerald tile converter, and a checker that every one of the 386 species has an obtainable source.

## Git

- `upstream` is `pret/pokeemerald`; `origin` is our repo. Never push to `upstream`.
- No enforced workflow. Use a branch and pull request for large or risky changes; small fixes can go straight to `main`.
- Keep our additions in clearly ours locations (`tools/ditto/`, `docs/ditto/`) so merging upstream updates stays easy.
