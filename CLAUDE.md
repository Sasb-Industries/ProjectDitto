# Project Ditto

A Game Boy Advance game built on the `pret/pokeemerald` decompilation. The goal is one game spanning Hoenn, Kanto (with the Sevii Islands) and Johto, with a single authored story route and all 386 Gen 1–3 Pokémon obtainable in one solo playthrough.

Decisions made so far, and the questions still open for the group, live in [docs/ditto/design.md](docs/ditto/design.md). Read it before proposing design changes; do not treat an open question as decided.

## Build and run

Requires devkitARM (`DEVKITARM=/opt/devkitpro/devkitARM`) and libpng.

```bash
make modern -j$(sysctl -n hw.ncpu)   # builds pokeemerald_modern.gba
open -a mGBA pokeemerald_modern.gba  # play it
```

- Always use `make modern`. Plain `make` needs the legacy agbcc compiler and tries to match the original ROM byte-for-byte, which no longer applies once we change anything.
- A full build takes about 45 seconds; incremental builds are a few seconds.
- After changing a tileset or graphics file, if the result looks stale, run `make tidymodern` and rebuild.
- "It builds" is the minimum bar for every change. For anything visible, also load the ROM in mGBA and look.

## Hard rules

- Never commit ROM files (`*.gba`), saves or build output. `.gitignore` already covers them; do not override it.
- Only Gen 1–3 content: 386 species, no later-gen Pokémon, moves, abilities or Megas. The one decided exception is the Fairy type, which is in; which Fairy moves and other Gen 6 type changes come with it is still open in the design doc, so ask before adding any.
- Levels are fixed per area and authored along the story route. Do not add runtime level scaling.
- One person or agent edits a given map at a time. `map.json` and `map.bin` merge badly.
- Kanto and Sevii content is ported from `pret/pokefirered`, keeping FireRed tilesets for now. Johto is converted from `pret/pokecrystal`, keeping Crystal's own tiles for now. Port layouts faithfully; redesign comes later. The Sevii Islands are not imported yet.

## Save-file space is nearly full

The build prints memory usage. On the unmodified game, `SaveBlock1` is 99% used, `SaveBlock2` 98% and `PokemonStorage` 94%. Every new flag, variable or saved struct costs save space we do not have. Before adding any, check `include/constants/flags.h` and `include/constants/vars.h` for unused entries to reuse, and report the new usage figures from the build output. ROM space is not a concern (43% of 32 MB used).

## Where things are

| What | Where |
|---|---|
| Map headers, events, connections, scripts | `data/maps/<MapName>/map.json`, `scripts.inc` |
| Map tile grids | `data/layouts/<LayoutName>/map.bin`, `border.bin`; index in `data/layouts/layouts.json` |
| Map list and groups | `data/maps/map_groups.json` |
| Tilesets | `data/tilesets/`, `src/data/tilesets/` |
| Wild encounters | `src/data/wild_encounters.json` |
| Trainers and their parties | `src/data/trainers.h`, `src/data/trainer_parties.h` |
| Species stats, evolutions | `src/data/pokemon/species_info.h`, `src/data/pokemon/evolution.h` |
| Moves | `src/data/battle_moves.h` |
| Flags and variables | `include/constants/flags.h`, `include/constants/vars.h` |
| Engine code | `src/`, headers in `include/` |

The `.inc` files beside each `map.json` (`header.inc`, `events.inc`, `connections.inc`) are generated by the build. Edit `map.json`, never those.

## Maps and Porymap

Humans edit maps in Porymap (open this folder as the project). Agents edit the same files directly: `map.json` is plain JSON, and `map.bin` is a grid of 16-bit little-endian values, one per tile, with the metatile id in the low 10 bits, collision in the next 2 and elevation in the top 4.

Our own tooling goes in `tools/ditto/` and is written in Python (needs Pillow).

- `render_map.py <MapName> out.png [--grid] [--collision] [--scale N]` draws a map as the game would, with warps in blue and NPCs in yellow. Use it to look at a map before and after editing it; `--grid` gives tile coordinates for placing events.
- `import_frlg.py <pokefirered checkout>` imports the Kanto mainland. See below.
- `import_crystal.py <pokecrystal checkout>` imports Johto. See below.

Still planned: a FireRed-to-Emerald retiler and a checker that every one of the 386 species has an obtainable source.

## Kanto

Kanto's 256 mainland maps (towns, routes, dungeons, interiors) and 51 tilesets were generated by `import_frlg.py`. Tileset symbols are `gTileset_Kanto*`, folders are `data/tilesets/*/kanto_*`, and map groups are `gMapGroup_Kanto*`. Two maps were renamed to avoid clashing with Hoenn: `Kanto_SafariZone_North` and `Kanto_VictoryRoad_1F`.

- The import brings layouts, tilesets, warps and connections only. Kanto has no NPCs, signs, items, trainers or wild encounters yet; each map has an empty `scripts.inc`. Add those by hand or with new tooling; FireRed's scripts cannot be copied because they rely on flags and specials this engine lacks.
- Re-running the importer is safe. It rewrites layouts, tilesets, warps and the blocks marked `ditto:import_frlg` in `src/data/tilesets/*.h` and `data/event_scripts.s`, and keeps each map's `object_events`, `coord_events`, `bg_events` and `scripts.inc`. Do not edit inside the marked blocks, and do not hand-edit Kanto tilesets or `map.bin` files unless you also stop re-running the importer for them.
- A Kanto secondary tileset only works with the Kanto primary it was built for (`KantoGeneral` outdoors, `KantoBuilding` indoors), because its first 128 tiles and metatiles and its palette 6 are the overflow of that primary. Never pair a Kanto tileset with a Hoenn one.
- Not ported: tileset animations (Kanto water, flowers and fountains are static), FireRed door animations, spinner tiles, and "press A" furniture descriptions.
- Hoenn and Kanto are joined by two placeholder sailors, in Littleroot Town at (10, 17) and Pallet Town at (9, 16). They exist to prove the link and should be replaced once region travel is designed.

## Johto

Johto's 230 maps and 34 tilesets were generated by `import_crystal.py` from `pret/pokecrystal` (commit `9ce4c4e`). This covers every Johto town, route, dungeon and interior, plus Routes 26–28, Tohjo Falls, Mt. Silver and the Fast Ship. It does not cover Crystal's Kanto, Indigo Plateau, Victory Road or the cable club, because FireRed's versions are used instead. Tileset symbols are `gTileset_Johto*`, folders are `data/tilesets/*/johto_*`, and map groups are `gMapGroup_Johto*`. Map names are Crystal's (`NewBarkTown`, `ElmsLab`, `Route29Route46Gate`).

- The graphics are Crystal's Game Boy Color tiles in their four original colours, with daytime palettes only. They are placeholders until GBA-style Johto tilesets exist.
- Each Crystal block (32×32 px) becomes four metatiles, so Johto maps are twice Crystal's size in each direction. Event coordinates are already in steps and match Crystal's exactly.
- Crystal sets palettes and roof graphics per map, not per tileset. So each Johto primary tileset has one or more secondary "variants" (`gTileset_Johto<Tileset>_<Variant>`) holding the map palettes in slots 6–12, the per-town roof tiles at tile 512, and any metatiles past 512. Only pair a Johto secondary with its own primary.
- Same scope as Kanto: layouts, tilesets, warps and connections only, with empty `scripts.inc` files. Warps to Crystal's Kanto maps loop back onto themselves.
- Not ported: tile animations, cut trees, whirlpools and headbutt trees as field-move obstacles (they are plain walls), Gold/Silver music (maps play FireRed and Emerald songs as placeholders), and region-map sections (`MAPSEC_NONE`, so no map-name popups).
- Re-running the importer is safe, with the same rules as Kanto: it rewrites the blocks marked `ditto:import_crystal` and keeps each map's events and `scripts.inc`.
- Kanto and Johto are joined by two placeholder sailors, in Pallet Town at (12, 16) and New Bark Town at (10, 9).

## Git

- The repo began as a snapshot of `pret/pokeemerald` at commit `731ad5bfd`, without its history. We do not merge upstream updates; to see why a line of original engine code exists, look at pret's repository.
- No enforced workflow. Use a branch and pull request for large or risky changes; small fixes can go straight to `main`.
